## End-To-End User Contract

### Start Or Continue

1. Pascal opens a normal Codex task on desktop or mobile and speaks naturally.
2. Ordinary bounded work stays Codex-only.
3. If the outcome must survive tasks, devices, time, repos, or executors, the
   Jarvis skill calls the one-step continuation contract.
4. One match is acquired and receives a bounded Context Packet. Zero matches
   returns `not_found`; several return `ambiguous` without binding anything.
5. The user is never required to learn `search -> start -> renew -> release`.

### Finish

1. The executor releases its run with artifact/effect evidence. This still
   does **not** complete the Matter.
2. Only Pascal's explicit words can authorize owner closure. The exact words
   enter the closure receipt; model prose, tests, exit code, or an artifact do
   not substitute for them.
3. Closure first retires linked Intents and pending Items, completes Handoffs,
   and then moves the Matter to `done`.
4. A live Matter Run, Job, or Delegation blocks the transition before any
   reconcilable state is changed.
5. The cross-store transition is idempotent and recoverable. A partial failure
   leaves the Matter open and can be replayed; a completed receipt is stable.

### Wake From Lark

Lark does not promise an unverified Codex deep link. It names the Matter and
uses a stable phrase such as `继续 Jarvis 事项「白皮书」（mat_...）`. Starting a
new Codex task with that phrase reaches the same one-step continuation path.
Programmatic task opening remains a separate acceptance item, not an implied
capability.

## Current Hard Gates

- Do not retire a Lark path before its corresponding desktop/mobile sample is
  accepted.
- Do not call a stack live because local tests or a PR passed.
- Do not infer Matter closure from a Result Receipt.
- Do not invent package allowance when the provider exposes none.
- Do not automate Phase 4 value judgments; L3 may prepare evidence and a
  Proposal, while Pascal decides what is worth sustaining.
