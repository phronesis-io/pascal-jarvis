# Jarvis 主动交流第一性原理：R21-R40 审计与实现

**状态：** 候选分支实现完成，待全量验证、独立审查与发布
**日期：** 2026-08-28
**范围：** Jarvis、Codex、Lark、Memorial、Matter、跨 Session 记忆
**一句话结论：** Pascal 主动想做一件事时打开 Codex；只有当正确时机不会等人、
外部世界在他离开时发生了重要变化、已托付工作产生了结果，或长期状态需要跨任务
协调时，Jarvis 才有资格主动找他。

## 一、第一性原理

人的注意力是系统最稀缺、最不可恢复的资源。一次主动消息不是免费输出，而是要求
Pascal 停下手头的事、切换上下文、理解内容并决定是否行动。因此：

> 一条 Jarvis 消息带来的预期价值，必须大于它造成的上下文切换成本。

这条消息还必须证明两个事实：

1. **为什么是现在。** 晚到会损失什么，或哪个异步事件刚刚完成；
2. **为什么必须找 Pascal。** 剩下的是判断、授权、时限、主动订阅的陪伴，还是他
   明确托付工作的结果，而不是 Jarvis 尚未完成的调查。

如果 Pascal 以后打开 Codex 再问也不会损失任何东西，就不应该现在打扰他。内容可
进入可检索账本、Matter 或批次，但不能伪装成一张需要看的卡。

Jarvis 主动交流只服务四个目标，按优先级排序：

1. **保护时间与机会。** 在期限、安全、日程或重要外部变化到来时及时出现；
2. **让托付真正异步。** Pascal 不必守着 Agent，完成、失败或只剩判断时再收到结果；
3. **减少重讲和遗忘。** 把跨 Session、跨产品的决定和下一步带回正确的 Codex 任务；
4. **提供经主动选择的陪伴与新知。** 只保留确实有回应、可随时停用的少数节奏。

“维持存在感”“让用户多跟 Jarvis 聊”“展示系统很努力”不是目标。如果一段时间没有
任何一项目标成立，零消息比为了活跃而发一张卡更好。

## 二、什么时候用 Codex，什么时候需要 Jarvis

| 情况 | 默认入口 | 原因 |
|---|---|---|
| 想提问、研究、写作、看文件、写代码、长分析或临时探索 | Codex 新任务 | 这是用户发起的前台工作，Codex 已有更好的任务、工具、文件和长内容体验 |
| 同一目标会跨天、跨设备、跨仓库或跨执行者 | Codex + 一个 Jarvis Matter | Codex 做当前工作，Jarvis 保存任务之外仍须成立的目标、决定、证据和下一步 |
| 想继续 Claude Code、Lark 或另一个 Codex 任务里的同一件事 | 新 Codex 任务 + Jarvis Context Packet | 新任务应干净；Jarvis 负责恢复正确且最小的长期上下文 |
| 到点提醒、期限临近、安全风险、外部人或系统发生重要变化 | Jarvis 主动唤醒 | 价值来自正确时机，不能要求 Pascal 先想起来再打开 Codex |
| 已托付的异步工作做完、失败或只剩本人判断 | Jarvis 返回结果 | Jarvis 承担“你不用守着等”的责任，并带工作和验证收据 |
| 日历、飞书联系人/群聊/审批等原生动作 | Codex 或 Lark 原生入口，Jarvis 仅在需持续跟进时介入 | 原生系统拥有对象真相，Jarvis 不做代理壳 |
| 系统自愈、重试、模型切换、队列清理成功 | 不发消息 | 这是后台职责，只留内部收据 |
| 普通健康状态、Agent 活动、可晚点查看的动态 | 账本或有界批次 | 活动不是用户价值 |

**直接和 Jarvis 聊天是例外：** Codex 没开时的快速捕捉、回复刚收到的时限/审批、
当前飞书会话里的原生沟通，以及 Codex 不可用时的降级。对话产生的持久内容最终仍要
进入 Matter；不能靠一个无限增长的 Jarvis Session 保存人生。

## 三、主动消息的八种合法理由

代码中的 `owner_need` 是人类理由，不是传输类型：

| `owner_need` | 何时成立 | 默认节奏 |
|---|---|---|
| `none` | 没有不可替代的人类需要 | 只进账本 |
| `judgment` | 研究和方案已经完成，只剩价值取舍 | 一个决策，必要时攒批 |
| `authority` | 外部、费用、权限、正式承诺或不可逆动作需要授权 | 一个明确授权 |
| `deadline` | 晚看会产生真实时间、安全或机会成本 | 立即，允许越过静默时段 |
| `requested_result` | Pascal 明确托付的异步工作刚得到可验证结果 | 一次结果回执 |
| `external_change` | 外部的人或权威状态发生了与当前目标相关的重要变化 | 聚合后一次通知 |
| `scheduled_companion` | Pascal 主动保留的 1-2 个陪伴节奏到点 | 可忽略、可随时停用 |
| `decision_batch` | 多个低时效判断合并后值得一次查看 | 每日最多一批 |

“有新消息”“Agent 运行了”“系统检测到异常”“模型说值得看”都不是独立理由。
`external_change` 必须是重要且相关的变化；`requested_result` 必须对应真实托付；
`scheduled_companion` 必须可退订。分类不认识时失败，不能默默落入一个会发卡的兜底。

## 四、一条合格消息长什么样

一条消息必须让 Pascal 在几秒内知道：

1. **结果或变化：** 发生了什么；
2. **已完成的工作：** Jarvis 已经调查、聚合、去重、修复或验证了什么；
3. **为什么现在：** 晚一点看会损失什么，或哪个托付刚刚结束；
4. **只剩什么给你：** 一个判断、一个授权，或明确“知道就行”；
5. **最小动作：** 一个自然回复、一个停止/以后再说选项，或去 Codex 继续同一 Matter。

长分析、完整证据、Diff 和产物留在 Codex。Lark 只承担一句可独立理解的唤醒；手机上
不能因为卡片长度而丢掉正文。若没有已完成工作收据和 `why_now`，消息不得进入飞书。

| 轮次 | 问题 | 结论与动作 | 状态 |

| R33 长内容 | 飞书看不完怎么办 | Lark 不复制长工作；正文和证据留 Codex，卡片只唤醒并保留可续读全文 | 既有实现保留 |
| R34 Codex 交接 | 唤醒后去哪里做 | 继续同一 Matter 的新 Codex 任务，不在飞书开第二份状态 | 既有连接层完成，20+20 实测未准出 |
| R35 跨 Session | 新任务为何还需要 Jarvis | Jarvis 编译当前有效 claim 和来源，不注入原始长对话 | 既有实现完成，长期回放待积累 |
| R36 沉默 | 用户不回复算什么 | 沉默不是同意、拒绝、验收或授权；不重复追问 | 既有验收协议完成 |
| R37 自愈 | 系统异常要不要汇报 | 能修就修并留账；只有时限/信任改变且仍需本人时才发 | 契约完成，需运行观察 |
| R38 渠道 | Codex/Lark/Jarvis 各干什么 | Codex 工作，Lark 唤醒/原生通信，Jarvis 连续性和控制 | 文档完成 |
| R39 度量 | 如何知道主动性变好了 | 看有用闭环/注意力，不看消息数；删除“24h 至少 5 张卡”健康观，改为只查真实投递债务，并新增结构化审计 CLI | 代码完成，基线已取 |
| R40 杀死测试 | 哪些 Jarvis 功能应淘汰 | 可被以后一次 Codex 提问无损替代、无 why-now、无本人需要者静默或退役 | 完成 |

“完成”只表示本候选分支已实现或既有权威机制已核对，不表示已合并、发布或通过真实
使用准出。Codex 手机/桌面 20+20、四周有用率与陪伴节奏仍必须由真实数据证明。

## 六、真实数据基线

2026-08-28 对生产只读复算：

- 近 7 天创建 151 张卡：19 张已处理、109 张自然过期；
- 同窗口折叠状态为 119 notice、22 decision、15 alert；
- 近 14 天回应率：`cross-session-sync` 2%、`morning-anchor` 0%、
  `eigenflux` 14%、`eigenflux-feed-triage` 18%；
- 近 7 天 156 个 Item 中，按兼容规则只有 21 个属于 `none`；135 个仍会进 Lark。
- 其中 9 个旧 Item 暴露语义错配：7 个普通邮件变化被当作 alert、1 个邮件草稿没有
  声明判断、1 个飞书授权问题被当作 alert；新生产入口已分别改为
  `deadline` / `judgment` / 非紧急 `authority`，历史记录不伪造迁移。

这说明此前系统的“主动”主要是生产消息，不是替人闭环。新契约首先把所有新的直接
发卡入口变成显式声明，并把 `none` 放回账本；它不会伪造历史字段，也不会根据一次
已读率宣称产品已经成功。

旧 `core.presence` 曾把“24 小时至少送达 5 张卡”当作健康地板。这会让系统为了证明
存在而制造打扰。本轮已改成按需健康：没有值得说的事可以是零消息；只有已承诺给
Pascal、经过真实尝试仍失败或卡住的 Lark 信封才形成投递债务告警。

上线后的四周目标：

- 普通主动打扰不超过 2/天，另有至多一个决策批次；
- 主动打扰有用率至少 70%；
- `owner_need` 显式覆盖率 100%，未知分类和无收据放行均为 0；
- 自愈成功消息为 0；
- 同一 Matter 重复询问为 0；
- 每个闭环 Matter 需要的 Pascal 消息数持续下降。

“有用”只由后续行动、显式保留反馈或 Pascal 主动再次引用计算。送达、已读、沉默、
模型自评和 Agent 活动都不算。

## 七、五个一票否决测试

任何一个答案为“是”，这条消息就不应立即发送：

1. Pascal 以后打开 Codex 再问也不会有损失吗？
2. Jarvis 还有能自己完成的调查、去重、修复或验证吗？
3. 说不清为什么必须现在看吗？
4. 说不清不可替代的 owner need 吗？
5. 这只是系统自愈、Agent 活动、健康快照或重复状态吗？

任何 Jarvis 功能若长期只能产出被这五条否决的消息，就应转为静默基础设施或删除。
