# Codex 与 Jarvis 日常使用指南

在 Codex 里直接问 `什么时候我需要 Jarvis，而不是只用 Codex？` 时，连接器会读取
版本化的 `jarvis_operating_model`，而不是让当前模型临场编一套答案。

## 一句话

你主动想做事时打开 Codex；需要事情在你没想起来时按正确时机找你、跨任务保持连续、
或把异步工作推进到只剩你的判断时，才需要 Jarvis。

## 每天默认怎么用

1. 在电脑或手机 Codex 为一个明确结果开一个新任务，直接说人话。
2. 提问、研究、写作、代码、文件、长分析和审查都留在 Codex。
3. 代码继续使用 Git/GitHub 看 Diff、Commit、PR、Review、CI 和 Merge。
4. 如果这件事会跨天、跨设备、跨 Session 或换 Agent，告诉 Codex：
   `这件事明天还要继续，帮我接到同一个 Jarvis 事项。`
5. 做完当前执行后，Codex 写回结果收据；只有你明确说
   `这件事完成了`，Jarvis 才关闭事项并收掉关联提醒和旧卡。

普通的一次性问题不创建 Matter，也不需要操作任何 Jarvis 命令。

## Jarvis 什么时候会主动找你

只有以下情况值得主动消息：

- 期限、日程、安全或机会窗口到了，晚看会有真实代价；
- 邮件、EigenFlux、联系人或权威状态发生了与你当前目标相关的重要变化；
- 你已经托付的异步工作完成、失败，或只剩你的判断；
- 外部发布、费用、权限、正式承诺或不可逆动作需要你授权；
- 你明确保留的少数陪伴节奏到了；
- 多个低时效判断已经攒成一个值得一次处理的批次。

Jarvis 自愈成功、模型自动切换、Agent 运行、普通健康快照和以后问 Codex 也不损失的
内容都不应该打扰你。没有值得说的事时，零消息是健康状态。

每条主动消息必须同时回答五件事：剩下为何需要你、Jarvis 已做完什么、为什么现在、
你只需做哪一个最小动作、不发会损失什么。缺任何一项就只记账，不进飞书。系统的
目标是保护时间、返回托付结果、带回重要外部变化、完成权威收口或履行你明确保留的
少数节奏；“让你多跟 Jarvis 聊”不是目标。

零消息本身不是故障。只有已经答应返回的结果、已经到期的提醒或已核验的重要变化
形成了投递债务，却仍没送达，才算需要后台自愈和运维关注。

## 什么时候直接在飞书和 Jarvis 说话

- Codex 没开时快速记下一件以后要继续的事；
- 回复 Jarvis 刚发来的期限、授权或决策；
- 当前动作本来就在飞书日历、文档、联系人、群聊或审批里；
- Codex 暂时不可用，需要降级沟通。

一旦进入研究、写作、代码、长分析或文件工作，就回到 Codex。飞书不是第二个长期
工作台，也不保存一段无限增长的上下文。

## 常用说法

在 Codex：

- `继续白皮书这件事，不要让我重讲之前的决定。`
- `这个工作会跨几天，接到一个 Jarvis 事项。`
- `我们之前关于模型备用链路最后决定了什么？`
- `现在真正需要我判断或收口的事情有哪些？`
- `这次实际用了什么模型，额度什么时候重置？`
- `这件事完成了，把相关旧提醒和卡片一起收掉。`

在飞书：

- `先记下，晚上在 Codex 继续。`
- `同意发布。`
- `这件事不用再提醒。`
- `去 Codex 继续。`

## 手机怎么用

手机上同样以 Codex 为主：新目标开新任务，继续旧目标时让它绑定原 Matter。长正文、
代码、文件和证据留在 Codex；飞书只给一条能独立看懂的唤醒。Jarvis 不再提供独立
手机网页、Tailscale 或配对码路径。

## 怎么知道系统真的变好了

不看它一天发了多少消息，而看：

- 继续旧事时是否不用重讲；
- Jarvis 是否先做完能代劳的工作；
- 一次回答是否收掉所有重复卡和提醒；
- 外部动作是否有权威读回而不是模型口头说完成；
- 每十分钟注意力闭环了多少有价值的事项。

首次迁移仍需要真实验收：桌面和手机各 20 次继续任务。Codex 只会在一次合格结果后
问一次简短反馈；忽略不会追问，沉默不会被当作通过。
